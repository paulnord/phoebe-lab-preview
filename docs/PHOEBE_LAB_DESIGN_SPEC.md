# PHOEBE Lab: developer design specification

**Purpose.** Let a learner or investigator see how an eclipsing binary's geometry changes its light and velocity curves, compare a physical model with observations, and refine it locally. This is a behavioral specification for maintenance or a clean-room rewrite, not a prescription for JavaScript, Python, a particular optimizer, or an emulator architecture. Preserve the science and observable interactions, not accidental implementation details.

**Baseline.** The feature inventory is pinned to [semi-detached commit 692b8c39](https://github.com/paulnord/phoebe-lab-preview/tree/692b8c3972ce3dca27df51bd9814919195c386b3), tree `f610f88dd2426f658b743249203e30a16e2f1d5f`, November 25, 2026. The locally audited public source baseline was `origin/main` at `8ad7999bdb9ade8c6056c8da41f35deb041f31cf`; the [public Pages app](https://paulnord.github.io/phoebe-lab-preview/) is a separate deployment, not proof that the feature branch is live there. Main already has the core detached workbench, browser workers, observation workflows, RV display and Advanced workspace. Treat the three-geometry main workbench, geometry-conditioned preview/mesh, and native Colab contract below as feature-branch behavior unless release evidence says otherwise. Colab multiworker support is outside this baseline.

Implementation aids: [source and tests](https://github.com/paulnord/phoebe-lab-preview/tree/692b8c3972ce3dca27df51bd9814919195c386b3), [Colab bridge verification](https://github.com/paulnord/phoebe-lab-preview/blob/692b8c3972ce3dca27df51bd9814919195c386b3/COLAB_NATIVE_RUNTIME.md), [published observations and loading instructions](https://github.com/paulnord/phoebe-lab-preview/blob/692b8c3972ce3dca27df51bd9814919195c386b3/site/examples/OBSERVATIONS.md).

## Runtime and state

| ID | Product contract |
| --- | --- |
| R01 | Standalone: the site serves static files and the device runs PHOEBE 2.5.4 through Pyodide/WebAssembly. No remote scientific backend, account, analytics or observational upload is required. An initial runtime download is required; browser cache is not an offline guarantee. An already-built site can be served over HTTP; opening an HTML file directly is not a supported deployment. A pinned raw.githack preview pins source and model files, but reuses published runtime artifacts; pin those separately for scientific reproduction. |
| R02 | Colab: **Run all** installs native PHOEBE, loads the bridge and launches the actual fitting workbench inside notebook output. The browser draws plots and runs instant approximations and playback. Exact curves, local optimization, final statistics/export data and constrained surface computations originate from the notebook's native Python PHOEBE process. Show startup, ready, failed and provenance states truthfully. Broken or absent bridge: disable exact work and offer recovery. **Never substitute browser PHOEBE for a Colab exact operation**, including via a file type or secondary UI route. The validation notebook is not the fitter. |
| R03 | Standalone supports 1–8 browser Web Workers for eligible exact surface phase batches, default 1; this is not MPI. Colab reports affinity/cgroup-limited CPU capacity and offers 1–4 persistent native Python phase workers when supported, selecting the truthful supported maximum by default while retaining every lower choice. Both paths keep the fast first batch on the primary worker, distribute disjoint phase indices with equivalent settings, and combine absolute flux before normalization. The fit search itself remains serial; its final authoritative curve may use the selected workers. Keep warm/cold latency and memory costs in mind. Do not advertise parallel execution unless it really occurs or imply parallel optimization trials. |
| R04 | Bind requests to data, geometry/donor, parameters and resolution. Cancel or supersede stale work; late old partials, finished curves, errors and meshes must not become current or unlock fit/export. Maintain a clear status for loading, waiting, partial, valid, stopped and failure. An earlier curve may be shown only as an explicitly labeled visual reference. Retry should recover a failed engine; stop must not corrupt a previous completed result. Native cancellation may be observed between batches, not necessarily inside a running call. If a reused PHOEBE curve bundle returns invalid samples, rebuild that geometry once and repeat the identical physical request before reporting a geometry failure; a second invalid result remains an error and must never be normalized or displayed. Colab status and that final error expose Python/PHOEBE/numerical-library versions plus the local Johnson V passband hash and invalid phase locations so hosted-only failures can be compared without editing hidden notebook cells. |

## Workbench and science

| ID | Product contract |
| --- | --- |
| M01 | Compact workbench with model controls, light curve and residuals, separate RV view, observation/example actions, fit controls/statistics, session save, help, and runtime indicator. Keep plots legible on wide screens without dropping content on smaller screens. Preserve numeric entry as well as slider input; retain reset and undo/redo of model edits. Distinguish **Fullscreen** (host permissions apply) from opening a fresh standalone window; don't relaunch standalone browser compute as a Colab fullscreen workaround. |
| M02 | Detached: two independently controlled radii as fractions of semimajor axis, inclination, temperature ratio, mass ratio (M_2/M_1), eccentricity, periastron angle, period, epoch. Optional tidal Roche distortion and companion irradiation. Baseline default circular detached parameters: inclination 84.5°, radii 0.21 and 0.17, temperature ratio 0.84, mass ratio 0.75, period 1.8 d, epoch 0, tides/heating off. |
| M03 | Semi-detached: circular; pick primary or secondary as the Roche-lobe-filling donor. Only the other star retains an independently adjustable radius. Recompute its allowed geometry, exact curve and surface when switching donor. Contact: circular; one common Roche envelope, controlled by fill-out rather than independent radii. Baseline fill-out limits 0.10–0.50, default 0.25. Do not silently fit parameters absent from the selected geometry. Display camera orientation is independent of physical eccentricity/periastron; it remains available in all modes. |
| M04 | Main model uses Johnson V, fixed 1.2 solar masses and 6,300 K for the primary, Keplerian orbit and PHOEBE atmosphere/limb-darkening settings. Baseline shared limits: inclination 0–90°, primary radius 0.10–0.32, secondary 0.08–0.29, temperature ratio 0.58–1.10, mass ratio 0.2–1.5, period 0.1–100 d, detached eccentricity 0–0.35 and periastron angle modulo 360°. Numeric bounds do not guarantee valid Roche geometry. Don't present circular constrained modes as a claim that eccentric mass transfer is impossible. |
| M05 | While dragging, show a clearly approximate preview only where defensible. Green identifies tested coverage, amber signals edge/sparse coverage, dashed red is an unvalidated boundary-held estimate; invalid geometry or no usable estimate produces no preview. Label omitted effects or atmospheric clamping where applicable. Exact PHOEBE on release is distinct from both the instant approximation and the potentially lower-resolution **Preview** mesh setting. Preview cannot become an authoritative result or enable export/statistics. The current detached display includes simplified discs and trained/reference corrections; constrained modes use geometry-specific trained artifacts. Target-neighborhood adapters add continuously sampled period-aware coverage around SZ Her (secondary donor) and V1128 Tau without using observed photometry as training targets; their exact picker presets remain held out for validation, and the original P=1.8 d constrained models remain unchanged. A rewrite may use another surrogate with separately measured coverage and error. |
| M06 | Progressive exact sampling: on uncached spherical/unheated detached curves, first 65 phases then nested grids to 513; eligible surface models start at five measured model phases and build to the selected target (usually 129; optional 513). Preserve ordering, coverage and truthful completion, not the exact batch sizes. Native exact initial phases are real evaluations, not a fabricated timer. Honor 400 triangles per star for detached Preview, 800 for constrained Preview, 1,500 for Refined when reproducing baseline. Switching quality or target must not mix incompatible results; matched stored or cached exact curves may be reused with compatible physics/passband/version and settings. |
| M07 | Residual plot follows the displayed work, distinguishing current exact, partial, preview and previous model. Final numeric statistics require the current completed exact grid. Optional faint preview/residual overlay, dashed previous fit/model, hover details and signed-log percent difference aid visual comparison. A preview/residual overlay is not a second scientific fit. |

## Observation, fit and output contracts

| ID | Product contract |
| --- | --- |
| D01 | Load delimited tabular photometry (CSV, TSV or whitespace), map coordinate, brightness and optional uncertainty, and explicitly select phase/time and flux/magnitude. Convert magnitudes and propagate uncertainties into relative flux. Time inputs require period and primary-eclipse epoch in the same time system as observations. No automatic UTC/HJD/BJD conversion. Surface missing/invalid data as a readable error, not an apparently successful fit. |
| D02 | Timestamped data retain original observation identity, time and optional uncertainty; show chronological and folded plots. Editable numeric period and epoch, zoomed sliders and fine stepping refold data; an epoch-only change may reuse a matched physical phase curve and redo comparison. Phase-zero marking and the time origin remain explicit. The period fit refolds the same observations at each trial; don't reorder weights away from their exposures. |
| D03 | Fit uses bounded local least squares near the current model, with 65/129/513 trial phases (129 default), selected physical parameters, and every observation; hold epoch fixed. Detached supports any valid subset of its eight physical sliders; reject fitting periastron alone on an exactly circular orbit. Semi-detached offers inclination, the free-star radius, temperature ratio, mass ratio and period. Contact offers inclination, fill-out, temperature ratio and mass ratio. Period is editable but not offered as a Contact fit checkbox at this baseline. Fit-dialog availability is a UI contract; do not expose an option merely because an internal API accepts it. Use the optimized parameters for the completed 513-point fit plot, reusing exact valid phases where possible. This is not a global solution, confidence interval, or proof of parameter identifiability. |
| D04 | Interpolate current model to the observations; choose one multiplicative normalization, using inverse-variance weights if supplied. For data `y_j`, model `m_j`, and weights `w_j`, scale `a = sum(w_j y_j m_j) / sum(w_j m_j²)`; residual `y_j − a m_j`; RMS is unweighted root mean square of residuals. Reduced chi-square is available only with usable uncertainties and positive degrees of freedom `N − 1 − k`, counting normalization and `k` fitted parameters. Use the completed phase grid for final comparison, not preview or an incomplete fit. |
| D05 | Save/load Lab session JSON (baseline schema `phoebe-lab-session-v1`) preserves model parameters, original observations and ephemeris, quality and curve phase setting; retain compatible RV data/offset when present. The session is not an engine checkpoint. Export phase/normalized-flux CSV and configurable SVG, vector PDF and PNG figures only for a current completed exact result. Figure controls independently show observations, exact curve, residuals and legend, offer sensible dimensions/PNG resolution, retain labeled axes without app chrome, and reject a figure containing neither observations nor model. Export a separate `phoebe-lab-parameters-v1` JSON and readable table for either the current parameter snapshot or current exact result; label unfitted, forward and fitted records distinctly, mark fitted versus held/fixed values, define q and phase zero, include data/model/engine provenance and statistics only when authoritative, and never invent uncertainties. Copy the table as tab-separated headers and values with numeric cells and a visible manual-copy fallback when iframe clipboard permission is denied. Changing parameters invalidates exact CSV/figure authority but still permits a clearly non-authoritative current parameter snapshot. Preserve readable source, model/geometry and numerical provenance even if a rewrite adds a richer format. |
| D06 | RV view presents both stars’ orbital line-of-sight velocities in km/s, positive receding, and displays semi-amplitudes; predictions update during a drag. Face-on velocities are zero relative to the system, opposite components follow barycentric motion, initialized examples or separate RV file may add either star and optional errors, and an optional systemic velocity aligns observations. Use the current period/epoch for time-based RVs. The axis may grow and stays comparable until explicit rescale. The main fitter is **photometry-only**; these are orbital velocities, not flux-weighted spectra or Rossiter–McLaughlin modeling. |

## Orbit and Advanced workspace

| ID | Product contract |
| --- | --- |
| V01 | Open the large animated orbit from the compact star guide or running-compute indicator. Play/pause, choose seconds per orbit, scrub phase, and keep phase/time and light curve linkage intelligible. Earth, overhead and user-rotatable camera share the same orbit; overhead Earth direction points down in the baseline. Azimuth/elevation and direct drag change viewing orientation, not simulation parameters. Separate zoom/reset, without spurious zoom when only rotating. Show depth and occultation clearly with opaque surfaces. |
| V02 | Show changing tidal silhouettes on detached shapes as appropriate, with constrained systems rendered from native phase-zero PHOEBE meshes (two lobe-shaped stars, or one connected contact envelope/neck); animate the cached co-rotating mesh without reevaluating every frame. Preview vs High detail changes mesh resolution (baseline High detail default). A failed/mismatched mathematical mesh is not authority to draw a fake valid contact envelope; make loading/errors and any illustrative geometry explicit. |
| A01 | Standalone Advanced PHOEBE is separate from the simplified lab. Open supported PHOEBE 2.x bundle/model files, including recognized JSON records; create from authoritative Lab or new detached/contact/either-donor templates. Retain components, compute configurations, datasets, models and settings. Inspect/edit queryable parameter catalog with constraints, units, choices and available flips; expose supported distributions, datasets, spots, RV offsets, GP and solver setup/check/run/adopt. View time-based series and model/solution results; export readable bundle/model and attach compatible model to bundle. Cancel preserves the prior document. Reject incompatible/unsafe records; don't promise external backends, all GP packages, remote jobs, or native desktop plotting. Colab baseline intentionally disables Advanced native project file routes (including array-form JSON) while permitting Lab sessions and observation tables. |

## Examples, regression checks and rewrite policy

- **Examples (E01).** The selector is usable from every geometry. Detached entries remain the original simulated binary, near Roche limit, grazing, deep primary, eccentric, non-eclipsing, and folded/unfolded KIC 4544587 with available RVs. Published-observation entries load SZ Her as semi-detached with the secondary donor and V1128 Tau as in-range contact, applying their documented starting guidance without creating errors or starting a fit. Preserve V1128 Tau's published deeper-minimum epoch HJD 2454842.3470 in provenance, but initialize the Lab/PHOEBE `t0_supconj` model alignment at the alternate conjunction, HJD 2454842.4996855 (one half-period later); label this explicitly as a model convention, not revised literature timing or a q inversion. Selecting an entry changes geometry when necessary and invalidates any stale exact result. Distinguish simulated data from measured catalog values. The observations guide also supplies GSC 3822-1056/LP UMa as a manual contact edge case whose published fill-out exceeds current bounds. Preserve citations, time system, ephemerides, units, passband, stated limitations and uncertainty availability. A successful import is not a verified scientific fit. Keep published-star RV and photometry validation datasets independent of preview training and record unsupported physics or domain failures explicitly in `experiments/published_validation/REPORT.md`.
- **Science boundaries (E02).** Display preview is not a scientific inference. Real-data fits can be affected by parameter degeneracy, passband differences, fixed temperatures/mass, spots or absent RV/uncertainties. Do not infer a unique mass ratio from partial-eclipse photometry. Preserve exact PHOEBE reference inputs and outputs; validate any replacement on profiles across eclipse, not only bulk RMS. Record passband bytes/version, mesh, phase grid, solver settings and tolerances.
- **Maintain (E03).** Treat IDs as the feature ledger. In every change that alters observable behavior, update the corresponding ID, evidence/test and release scope in the same PR. Mark experimental work, exclusions and not-yet-verified environments separately. Do not claim support from a screenshot, UI label or unit tests alone. A rewrite may improve batching, camera rendering or numerical implementation if it meets the contracts or explicitly proposes and validates a behavior change.
- **Distribute (E04).** Keep scientific dependencies reproducible, with version and source/license notices as applicable. A deployable static artifact includes built engine/runtime and assets, not just repository HTML. Notebook URLs pin the file if commit-based; verify also which source archive/runtime the notebook actually loads.
